# INFOTECS

## Краткое описание
**INFOTECS** — проект, созданный в рамках тестового задания для поступления на стажировку в компанию INFOTECS. Он включает в себя:
- библиотеку **LIB** для логирования в файл и/или в сокет;
- интерактивное приложение **UA** для записи логов в файл и/или в сокет;
- серверное статистическое приложение **SA** для получения логов из сокета;
- модульное тестирование библиотеки.

## Архитектура проекта
# Паттерны проектирования
- Singleton – логгеры (FileLogger, SocketLogger) и контроллеры приложений.
- Strategy – интерфейс ILogger с реализациями для файла и сокета.
- Command – команды меню UA (LOG, CHANGE, HELP, EXIT) как отдельные классы.
- Producer-Consumer – BusinessWorker с очередью задач и потоком-воркером для асинхронной записи логов.

### Модули
- LIB – библиотека логирования: файловый и сокетный логгеры с общим интерфейсом; потокобезопасны, используют атомарный уровень важности и мьютексы.
- UA (User App) – интерактивное приложение: цикл ввода команд, парсинг токенов, асинхронное логирование через BusinessWorker, опциональное подключение сокетного логгера.
- SA (Stat App) – сервер статистики: приём сообщений по TCP, сбор статистики (количество, уровни, длины, сообщения за час), вывод по таймауту и после N сообщений.
- common – BusinessWorker (пул задач) и JoinThread (безопасное завершение потока).

### Взаимодействие
UA → LIB (файл и/или сокет) → SA (приём данных из сокета).
Все компоненты обмениваются кодами ошибок (без исключений) через единые API-слои (fl_api, sl_api, stat_controller_api).

## Перед сборкой
Для использования сокета для логов необходимо знать IP-адрес PC. Для тестирования SA и UA на одном PC используйте 127.0.0.1. Если же есть необходимость тестировать программы на разных PC, то нужно узнать локальный IP этого PC с помощью программы:
```bash
hostname -I
```
**NB**: прошу обратить особое внимание, что для корректного запуска всех модулей проекта необходимо находиться непосредственно в папке **build**.


## Сборка и запуск
### Конфигурация и cборка **LIB**
**NB**: сборка библиотеки доступна в 2 версиях: динамической и статической. По умолчанию сборка статическая, однако, если требуется динамическая, следует добавить флаг **UILD_SHARED_LIBS**. Например:
#### Для статической сборки:
```bash
git clone -b main https://github.com/naumnovikov/INFOTECS.git
cd INFOTECS
mkdir build && cd build
cmake .. -DBUILD_LIB=ON
make LIB
```
#### Для динамической сборки:
```bash
git clone -b main https://github.com/naumnovikov/INFOTECS.git
cd INFOTECS
mkdir build && cd build
cmake .. -DBUILD_LIB=ON  -DBUILD_SHARED_LIBS=ON
make LIB
```
### Конфигурация, cборка и запуск **UA**
**NB**: при неправильно закрытой предыдущей рабочей сессии (не командой EXIT), при запуске UA может выходить segmentation fault. Для того, чтобы запустить программу, требуется подождать некоторое время, чтобы ОС почистила ресурсы от предыдущей сессии.
Также стоит учесть, что UA использует LIB, поэтому при сборке обязательно подключать и LIB.
```bash
git clone -b main https://github.com/naumnovikov/INFOTECS.git
cd INFOTECS
mkdir build && cd build
cmake .. -DBUILD_LIB=ON -DBUILD_USER_APP=ON
make UA
```

**NB**: конфигурация UA происходит прямо в командной строке. Общий формат запуска:
```bash
./src/user_app/UA <log_filename> <DEBUG|INFO|ERROR> [ip:port]
```
#### Для конфигурации исключительно с файловым логгером:
```bash
./src/user_app/UA logs.txt DEBUG
```
#### Для конфигурации и с файловым, и с сокетовым логгером:
```bash
./src/user_app/UA logs.txt INFO 127.0.0.1:9000
```
#### Конфигурация, cборка и запуск **SA**
```bash
git clone -b main https://github.com/naumnovikov/INFOTECS.git
cd INFOTECS
mkdir build && cd build
cmake .. -DBUILD_STAT_APP=ON
make SA
```
**NB**: конфигурация SA происходит прямо в командной строке. Общий формат запуска:
```bash
./src/stat_app/stat_app <port> <N> <T>
```
#### Для конфигурации с портом 9000, статистическим лимитом 5 и таймаутом 10 сек.:
```bash
./src/stat_app/stat_app 9000 5 10
```
### Конфигурация, cборка и запуск **TESTS**
**NB**: TESTS используют LIB, поэтому при сборке обязательно подключать и LIB.
```bash
git clone -b main https://github.com/naumnovikov/INFOTECS.git
cd INFOTECS
mkdir build && cd build
cmake .. -DBUILD_LIB=ON -DBUILD_TESTS=ON
make TESTS
./tests/TESTS
```

## Использование UA
### Приложение имеет 4 команды:
- CHANGE - для изменения дефолтного уровня логирования (по умолчанию debug);
- LOG - для непосредственного логирования;
- HELP - вызвать помощь;
- EXIT - корректный выход из приложения.
### Существуют 3 уровня логирования:
0) debug;
1) info;
2) error.
По желанию **состав уровней можно изменить** - для этого нужно всего лишь добавить/удалить поле в/из enum class LogLevel.
# Особенности: 
- регистронезависимо;
- лишние аргументы пропускаются (за исключением LOG);
- лишние пробелы пропускаются;
- логировать можно без указания уровня (будет использован debug);
- LOG можно писать с "";
- если указанный лог-файл существует в /build, то новые логи будут записываться туда;
- если указанный лог-файл отсутствует, то логи будут писаться в новый файл.
### Примеры команд:
```bash
LOG "Your message here" DEBUG
LOG "Your message here"
LOG YourMessage INFO
LOG YourMessage
CHANGE INFO
CHANGE debug
HELP
EXIT
```

## Использование SA
После запуска приложение принимает 1 любое подключение (в будущем есть архитектурный задел под множественное логирование). Если с истечением TTL = 120 не будет подключений, то SA само выключится.
По ТЗ была реализована логика вывода статистики при изменении по сравнению с предыдущим выводом либо с истеченим таймаута, либо с достижением лимита количества принятых сообщений.
Кроме всего, всегда выводятся в консоль залогированные сообщения.
